# 从粘贴内容到可信结构化信息

Label: wayfinder:map

## Destination

形成一份可评审的产品与架构决策说明：定义用户希望从粘贴内容中得到的信息、可信提取的验收标准、可行的系统形态，以及从当前产品转向该目标所需的约束和迁移决策。现有十二类解析器和 OTA 模块不是方案前提。

## Notes

- 本地图只解决决策，实施、发布和代码迁移在路线清晰后另行开展。
- 旧需求和代码用于发现真实用户行为、数据兼容性与风险；不据此预设新系统的数据模型或算法。
- 私有离线、单文件交付、现有工作空间兼容性及“表格”边界均需明确决策。
- 决策会话使用 grilling 与 domain-modeling；外部技术事实优先由 research 调查，交互不清楚时用 prototype 呈现。
- 遵守本仓库 main 分支工作约定，不创建分支、工作树或 PR。
- 用户已授权提前制作评估样本与可丢弃原型；它们是探针，不提前解决仍受产品边界阻塞的决策票。

## Decisions so far

- [研究不依赖格式目录的自动结构发现](issues/04-research-structure-discovery.md)：无监督结构归纳需要重复证据和归纳偏好；MDL 只负责排序，可信结果还需要来源与遗漏内容的可核查契约。
- [研究示例驱动与交互式信息提取](issues/05-research-example-guided-extraction.md)：少量示例能表达提取意图，候选分歧可用于主动澄清；逐字段标注与错误泛化仍需控制。

## Not yet specified

- 在目标范围确定后，界定信息是单元格、表格、键值、实体关系，还是更一般的结构；再明确与筛选、JOIN 和导出的关系。
- 在可信结果的含义确定后，细化来源位置、遗漏内容、多个合理解释、用户纠错和确认机制。
- 在系统形态确定后，细化本地模型、规则归纳及用户标注各自的实际计算预算和反馈节奏。
- 在新结果契约确定后，界定旧工作空间、CLI 数据和保存的单元格修正如何处理。

## Out of scope

- 直接实施重构、替换发布产物或迁移用户数据；这些工作在本地图形成决策说明后规划。
