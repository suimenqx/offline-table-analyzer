# 真实样本与人工复核协议（待执行）

## 目标

判断信息提取草稿能否让用户更快、更准确地得到所需表、字段、记录和关系，同时保留未提取但有用的上下文。本轮自动运行的 [报告](report.md)只验证小样本上的零交互输出；它没有测量用户任务完成情况。

## 样本提交

优先收集经脱敏的实际粘贴内容。每份保留换行、空格、制表符、引号及表格边框；这些字符可能决定结构。把姓名、账号、密钥、地址等敏感值替换成结构相同的假值，并注明替换是否改变了字符宽度。不要提交真实密钥或客户数据。

每份样本附五项说明：

1. 原文来自哪类工作：例如命令行输出、网页复制、电子表格、诊断日志；无须提供真实系统名。
2. 本次任务希望得到哪些表、字段和记录。可用 TSV 或简单 Markdown 表格给出期望输出。
3. 哪些标题、注释、汇总或错误文本必须保留供审阅，但不应进入数据表。
4. 是否需要表间关联；若需要，明确左右字段、关系的业务含义，以及是否应由用户确认。
5. 哪些地方允许多种合理解释；记录“暂不提取”是否可接受。

至少覆盖常见输入、两种布局混合、短片段歧义、错误/截断输入、没有表格的负例。当前仓库样本可作为起点，不能替代真实使用样本。

## 对照操作

同一参与者对同一份输入分别使用当前 [正式单文件应用](../../../index.html) 与 [可丢弃提取原型](prototype.html)。用不同样本交替两种工具的先后顺序，减少学习顺序偏差。开始前只说明任务目标；不要提前展示标准答案。

每次记录：

| 字段 | 记录方式 |
| --- | --- |
| 任务完成 | 用户认为已得到目标结果时停止计时；放弃也记录。 |
| 时间 | 从粘贴到用户宣布完成的秒数；若只是研究者操作，注明不代表真实用户。 |
| 操作 | 手动改格式、改表头、圈选补提、改字段、排除误表、确认关系等次数。 |
| 错误 | 与标准答案比对错字段、漏字段、错记录、漏记录、错表边界、错关联。 |
| 未发现错误 | 用户宣布完成后仍存在的错误单列；它比可见且已修正的错误更危险。 |
| 来源/遗漏 | 用户能否定位每个关键值的原文；重要表外内容是否仍可见。 |
| 弃答 | 系统是否明确表示证据不足；用户是否能理解下一步操作。 |

人工审阅先评价最终结果，再评价工具给出的初始草稿。对关系候选要分开统计“建议正确”和“未经确认就执行 JOIN”；后者应视为更高风险。

## 进入正式重构设计的门槛

在看真实样本结果前，由产品负责人和目标用户共同写下门槛。至少要求：已知格式任务不能明显退步；混合/陌生输入有可重复的净收益；重要错提和错关联不会因界面而更难被发现；完成时间与纠错成本可接受；移动设备和离线单文件交付成本可估算。不要用本仓库人工构造的样本反推这些门槛。
