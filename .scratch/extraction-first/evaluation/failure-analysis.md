# 原型保留样本失败归因

本分析回答：原型在四个冻结后加入的项目样本中只完全吻合一个，究竟是偶然代码错误，还是提取方案边界？此前的[对照报告](report.md)只记录结果，没有完成这种归因。下列结论基于现有源码、逐例输出和只改变一个因素的最小对照输入；不把项目样本当成真实用户分布。

## 复现信号

运行 node .scratch/extraction-first/evaluation/evaluate.mjs，检查 [results.json](results.json) 中的 holdout 样本。当前结果稳定为：现有 ImportEngine 四例完全吻合，原型仅 Markdown 转义管道符一例完全吻合。原型前三个失败分别是：

| 样本 | 直接可见的错误 |
| --- | --- |
| 多行引号 CSV | 只输出第一条记录的前半个字段；把引号内换行后的内容和第二条记录留在未解释原文中。表头正确，记录与字段值被截断。 |
| HTML 表格 | 输出零张表；整段 HTML 源码留在未解释原文中。 |
| 多块定宽 CLI | 只输出第二张 Resource allocation 表；第一张含多词描述的表全部留在未解释原文中。 |

“仍在未解释原文”意味着原始字符没有静默消失，但用户要的结构化信息仍然缺失，不能计为成功提取。

## 最小对照与机制

| 失败 | 一次只改变一个因素的对照 | 机制定位 | 类型与修复代价 |
| --- | --- | --- | --- |
| 多行 CSV | 带引号字段中的内容由 a 换行 b 改为 a 空格 b 后，原型从截断记录变为完整记录。 | [原型的 lines 与 tokenize](prototype.html)先按物理行切分，逐行重置引号状态；[当前 Delimited.parse](../../../src/parsing/delimited-utils.js)让引号状态跨换行延续。候选评分和表头判断不是主因。 | **局部算法实现缺口。** 可以先构造带原文范围的逻辑记录，再做字段分割；需要处理转义引号、CRLF、未闭合引号与多行来源范围。无需推翻“来源可追溯的提取结果”契约。 |
| HTML | 一行 HTML 输出零表；仅在行标签后插入物理换行仍输出零表。 | 原型只找至少两行、每行至少两个分隔字段的重复结构；它从未把 HTML 行、单元格标签变成记录/单元格。当前 [HTML parser](../../../src/parsing/parsers/html-parser.js)明确识别表、行、单元格、合并单元格和可读文本。 | **输入表示的架构缺口。** 需要 HTML 结构前端，或把 DOM/标签区域转换为统一的来源区域图，再进行字段/记录归纳。不能靠调高候选分数解决；原始 HTML 字符偏移与 DOM 文本位置的对应也是成本。 |
| 多词 CLI 定宽列 | 两列样本中的值 two words 无法成表；只把值改为 two_words 就得到两列表。 | [原型的空白切词](prototype.html)把每个非空白词当一个字段，第一行宽度 2、第二行宽度 3；[候选搜索](prototype.html)要求行宽一致，因此丢弃第一块。当前 [CLI 多块解析器](../../../src/parsing/parsers/cli-multi-block-parser.js)使用显示列范围与位置截取，并在异常时反馈诊断。 | **结构归纳能力缺口。** 需要跨行列起点、显示宽度和块边界推断；这可以作为通用空间布局原语实现，但已明显超出“简单按空格切词”。还需验证短片段、汉字宽度和列内空格的误切成本。 |

第四个保留样本的 Markdown 转义管道符两者都通过，说明原型并非所有特殊转义都会失败；这不能反证上述三个独立机制。

## 对“方案缺陷还是实现问题”的回答

- **不是可追溯信息提取这一产品方向被证伪。** 三例失败发生在从原文形成记录/单元格候选之前；来源范围、未解释片段和人工修正的结果契约仍可表达正确输出。
- **也不只是三个小 bug。** HTML 需要树形输入表示，CLI 需要二维位置结构；若继续补齐能力，通用提取器必须引入更丰富的词法与布局原语，或使用多个来源前端。其代码量、维护和解释成本需要重新估算。
- **当前原型的“格式无关且极简”的算法假设未通过这组保留样本。** 物理行、五种分隔候选与等宽连续行的归纳偏好太窄。是否有更强、仍值得部署的统一归纳器，不能由这四例证明或否定。

因此下一轮要分开比较两件事：一是**提取结果契约**能否显著降低错提、漏提和审阅时间；二是为这个契约提供结果的**发现算法**能否在已知格式不退步的同时改进混合与陌生输入。把两者绑成一个“新方案”会误判其收益与代价。

## 后续可证伪实验

1. 在明确标记的可丢弃评估目录中，分别加入跨行引号记录、HTML 区域表示、显示列布局推断，每次只补一个能力，并检查保留样本与此前混合样本是否同时受益。仓库约定要求直接在 main，不改正式发布产物。
2. 加入未参与这些设计的脱敏真实输入，特别是多行单元格、嵌套 HTML、列内空格、标题与表混排的组合；先由目标用户标注期望结果，再评估。
3. 记录误提的严重度和人工修正成本。只提高已知格式的自动吻合率，却让错误来源或漏项更难发现，也不足以支持重构。
