# 自动识别优化计划

## 目标

提升自动格式识别、自动表头推断和数据完整性保护，重点解决“格式分数高但解析结果为空”“错误格式改变列结构”“定宽解析静默截断”三类问题。

## 已实施的第一阶段

1. 分隔符识别必须有真实的分隔符证据；无逗号文本不再获得 CSV 兜底分。
2. CSV/TSV 的分隔符统计复用引号感知解析，避免引号字段中的 Tab 干扰格式判断。
3. ASCII 表格要求至少两个强边框行和至少两行数据，普通 `---` 不再触发。
4. 定宽对齐格式要求同时存在可识别的多列头行和数据行。
5. 自动识别会对候选执行轻量解析质量校验；候选无法生成表格时自动尝试后续候选。
6. 表头阈值从 0.55 提升到 0.65，增加中英文常见字段名，并返回表头置信度和判断理由。
7. 定宽对齐数据行发现位置偏移时，优先使用空白分隔结果保留溢出值，并发出 `ALIGNED_POSITION_MISMATCH` 诊断。
8. 新增空白文本、引号内 Tab、原始 HTML、ASCII 误判、歧义字符串行和定宽溢出的回归测试。
9. 定宽对齐解析改为独立的 `TextLayout` 推断：以数据行的稳定列起点为主证据，结合表头语义和类型差异判断“列头还是表名”，支持多词列头和多词数据单元格。

## 第二阶段：候选确认与结构区域提取

已落地的策略把“格式选择”和“表格区域提取”分开处理：

1. 格式候选在有界完整记录样本上解析评分并生成有界表格指纹。候选分差低于 `0.12` 或最高分低于 `0.55`，且领先候选产生不同的规范化表格时，才要求用户选择；弱但具备表格形状的单一候选或等价候选先显示最佳结果并给出检查提示，无稳定表格形状的弱纯文本回退标为未识别。分数只用于排序，不代表正确概率。
2. 上次成功格式不再打破候选平局。硬结构签名和用户手动选择仍优先。
3. 对 CSV、分号 CSV、TSV、pipe、固定宽度和对齐文本扫描一个或多个连续区域；分隔符扫描遵守引号和嵌入换行。稳定区域分别解析并附带原文偏移；与这些结构行不连续、且不含相同列分隔结构的外围说明文字不进入表格。
4. 同一区域行宽不一致时直接解析；沿用现有规范化契约保留溢出单元格并显示诊断。过多候选区域仍明确要求拆分输入。
5. 自动表头信心低于 `0.65` 时保留自动推断结果，并在预览区提供“首行作为表头/首行作为数据”快捷切换。用户选择只在当前来源上下文内生效。
6. 真正不同的格式候选在预览区显示有界样例并提供一次选择；其他弱证据通过结果旁警告和快捷切换提示。只有未解决的实质格式歧义会阻止导出。

当前区域定位是结构启发式首版，支持格式范围见架构文档。真实失败样例仍未提供；后续评估应按输入族补齐脱敏样本，记录目标区域、表头、行列、源偏移和关键单元格，并比较区域召回、边界准确率、单元格精确率、静默错拆率、确认率和运行预算。不要把合成边界用例的通过当成真实准确率结论。

### 实现备注

- **评分权重**：候选分 = 指纹分 × 0.72 + 解析质量 × 0.18 + 形状证据 + 区域证据 × 0.4，封顶 1。指纹是主信号，解析质量和形状仅作确认；区域证据只在样本整体矩形时参与，且上限 0.08 远低于歧义阈 0.12，不会凭区域证据打破平局。全部数值只用于排序，不是正确概率。
- **采样扩展**：截断样本上 plain-text 自信胜出时，继续在 16,384/65,536/262,144 预算内扩展采样，避免长说明文字前缀掩盖后续表格区域（有回归测试锁定）。
- **定宽区域近似**：`findFixedWidthRegions` 以连续两空格以上（`\s{2,}`）切分列宽，是对 FixedWidthParser 自身 TextLayout 布局推断的简化；边界可能与真实列边界有偏差，但区域内容仍由真实解析器重解析，偏差仅限区域边缘。已知限制，待真实脱敏样例验证。
- **已知限制（暂不修）**：格式指纹的按行均值存在性阈值（如逗号均数 > 0.15）会稀释长说明文字前缀后的小表格，导致分隔符格式不被提名；此时结果保持 plain-text 而非猜测。这需要区域感知的候选提名，属于新的检测能力，不在当前范围内。

### 区域提取评估工具

`npm run eval:regions` 跑 `tools/region-eval.mjs`，样例族在 `tools/region-eval-fixtures.mjs`。每个样例记录目标区域（原文偏移）、表头、行列和关键单元格，报告区域召回、边界准确率（|Δstart|+|Δend| 均值与精确率）、单元格精确率、静默错拆/漏并、确认率和单次解析耗时（p50/p95/max）。当前样例全部为合成数据：任何与设计行为不符即非零退出（回归门）；但样例通过不代表真实准确率，真实脱敏样例按输入族补入 fixtures 后指标才有结论意义。

## 第三阶段：用字段完整性判别相近分隔符

已进入格式确认的两个候选如果分别使用逗号与分号或 Tab，而且样本覆盖的所有区域及记录数一致、两种切法各自列宽稳定，就由 `Delimited` 在同一段样本上比较原始记录。支持自动选择的证据是一个重复的带小数逗号的时间列，或至少两个重复的小数逗号数值列。每个支持列至少需要三条、且占该区域记录数至少 75% 的完整值在另一种切法中消失。每个区域都要提供证据，单列小数的两可输入仍会提示确认。比较使用原始记录，选定后由解析器按原有规则推断表头，输出单元格保持字符串。

将行结构和值类型一起用于判别的依据见 [Van den Burg 等人的 CSV 方言检测研究](https://arxiv.org/abs/1811.11242)。

在 `npm run eval:regions` 的同一批 16 个合成样例上，基线 `536a336` 需要 5 次格式确认，本轮需要 2 次。两个真正两可的样例都保留了确认，确认后的评估结果共匹配 17 个区域和 175 个预期单元格。

取其中 6 个单表分隔符样例，比较各工具报告的分隔符。四个样例有指定正确切法，两个样例的验收要求是保留确认。Python 和 CleverCSV 的候选限制为逗号、分号和 Tab，DuckDB 使用默认 `sniff_csv`。

| 判别方式 | 明确样例选对 | 两可样例保留确认 |
| --- | ---: | ---: |
| 项目基线 `536a336` | 1/4 | 2/2 |
| Python 3.12.1 `csv.Sniffer` | 2/4 | 0/2 |
| CleverCSV 0.8.5 `Detector` | 3/4 | 1/2 |
| DuckDB 2.0.1 `sniff_csv` | 2/4 | 0/2 |
| 项目本轮字段完整性判别 | 4/4 | 2/2 |

上述比较的适用范围是这组有针对性的合成样例。真实输入上的收益仍需用脱敏样例评估。

## 验收标准

- 标准 CSV、TSV、HTML、Markdown、ASCII、CLI、固定宽度和定宽对齐样例保持通过。
- 无分隔符的空白文本不再被识别为 CSV。
- 合法 CSV 引号字段中的 Tab 不改变格式判断。
- 纯水平线不再产生空的定宽对齐结果。
- 定宽对齐值发生位置偏移时不静默丢失内容，并有诊断信息。
- 混杂说明文字的分隔表提取为单独区域，多个区域分别返回并附带来源偏移。
- 行宽不一致时自动保留数据并显示诊断；单一弱格式候选及不确定表头都有可见提示和就地切换。
- 只有不同候选产生实质不同结果且证据不足时才阻止自动选择；确认位于预览旁，导出在该格式选择完成前被阻止。
- 原始单元格值和溢出内容保真；解析候选预览将导入文本作为文本而非 HTML 渲染。
- 构建产物、全量回归测试和发布校验全部通过。
