# 自动识别优化计划

## 目标

提升自动格式识别、自动表头推断和数据完整性保护，重点解决“格式分数高但解析结果为空”“错误格式改变列结构”“定宽解析静默截断”三类问题。

## 已实施的第一阶段

1. 分隔符识别必须有真实的分隔符证据；无逗号文本不再获得 CSV 兜底分。
2. CSV/TSV 的分隔符统计复用引号感知解析，避免引号字段中的 Tab 干扰格式判断。
3. ASCII 表格要求至少两个强边框行和至少两行数据，普通 `---` 不再触发。
4. 定宽对齐格式要求同时存在可识别的多列头行和数据行。
5. 自动识别会对候选执行轻量解析质量校验；候选无法生成表格时自动尝试后续候选。
6. 表头阈值从 0.55 提升到 0.65，增加中英文常见字段名，并返回表头置信度和判断理由。
7. 定宽对齐数据行发现位置偏移时，优先使用空白分隔结果保留溢出值，并发出 `ALIGNED_POSITION_MISMATCH` 诊断。
8. 新增空白文本、引号内 Tab、原始 HTML、ASCII 误判、歧义字符串行和定宽溢出的回归测试。
9. 定宽对齐解析改为独立的 `TextLayout` 推断：以数据行的稳定列起点为主证据，结合表头语义和类型差异判断“列头还是表名”，支持多词列头和多词数据单元格。

## 第二阶段：候选确认与结构区域提取

已落地的策略把“格式选择”和“表格区域提取”分开处理：

1. 格式候选在有界完整记录样本上解析评分。非结构型候选分差低于 `0.12`，或最高候选分低于 `0.55` 时，不返回猜测表；用户必须选择格式。分数只用于候选排序，不代表正确概率。
2. 上次成功格式不再打破候选平局。硬结构签名和用户手动选择仍优先。
3. 对 CSV、分号 CSV、TSV、pipe、固定宽度和对齐文本扫描一个或多个连续区域；分隔符扫描遵守引号和嵌入换行。稳定区域分别解析并附带原文偏移；与这些结构行不连续、且不含相同列分隔结构的外围说明文字不进入表格。
4. 同一区域行宽不一致时先显示确认候选；确认后沿用现有规范化契约保留溢出单元格并产生诊断。过多候选区域则明确要求拆分输入。
5. 自动表头信心低于 `0.65` 时停止返回猜测表，提供“首行作为表头/首行作为数据”两种重解析动作。用户选择只在当前来源上下文内生效。
6. 解析详情显示候选区域范围、行列稳定度和有限原文预览；预览按文本安全渲染。导出在歧义尚未解决时被阻止。

当前区域定位是结构启发式首版，支持格式范围见架构文档。真实失败样例仍未提供；后续评估应按输入族补齐脱敏样本，记录目标区域、表头、行列、源偏移和关键单元格，并比较区域召回、边界准确率、单元格精确率、静默错拆率、确认率和运行预算。不要把合成边界用例的通过当成真实准确率结论。

### 实现备注

- **评分权重**：候选分 = 指纹分 × 0.72 + 解析质量 × 0.18 + 形状证据 + 区域证据 × 0.4，封顶 1。指纹是主信号，解析质量和形状仅作确认；区域证据只在样本整体矩形时参与，且上限 0.08 远低于歧义阈 0.12，不会凭区域证据打破平局。全部数值只用于排序，不是正确概率。
- **采样扩展**：截断样本上 plain-text 自信胜出时，继续在 16,384/65,536/262,144 预算内扩展采样，避免长说明文字前缀掩盖后续表格区域（有回归测试锁定）。
- **定宽区域近似**：`findFixedWidthRegions` 以连续两空格以上（`\s{2,}`）切分列宽，是对 FixedWidthParser 自身 TextLayout 布局推断的简化；边界可能与真实列边界有偏差，但区域内容仍由真实解析器重解析，偏差仅限区域边缘。已知限制，待真实脱敏样例验证。
- **已知限制（暂不修）**：格式指纹的按行均值存在性阈值（如逗号均数 > 0.15）会稀释长说明文字前缀后的小表格，导致分隔符格式不被提名；此时结果保持 plain-text 而非猜测。这需要区域感知的候选提名，属于新的检测能力，不在当前范围内。

## 验收标准

- 标准 CSV、TSV、HTML、Markdown、ASCII、CLI、固定宽度和定宽对齐样例保持通过。
- 无分隔符的空白文本不再被识别为 CSV。
- 合法 CSV 引号字段中的 Tab 不改变格式判断。
- 纯水平线不再产生空的定宽对齐结果。
- 定宽对齐值发生位置偏移时不静默丢失内容，并有诊断信息。
- 混杂说明文字的分隔表提取为单独区域，多个区域分别返回并附带来源偏移。
- 分隔行宽、格式候选或表头证据不足时不产生静默猜测结果；用户确认后重解析。
- 原始单元格值和溢出内容保真；解析候选预览将导入文本作为文本而非 HTML 渲染。
- 构建产物、全量回归测试和发布校验全部通过。
