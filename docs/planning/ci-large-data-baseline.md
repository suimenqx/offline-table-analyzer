# 10 万行 × 32 字段：桌面 Chromium 实测基线

下面是动作墙钟时间，包含自动化检查和两帧等待，排除固定观察尾段；不能当作真实用户 INP。短字段是三次中位数，中文与长字段各只有一次。

| 解析与首次预览 | 1,446.7 | 1,443.7 |
| 翻到第 2 / 3 / 4 页 | 248.3 / 337.1 / 357.9 | 240.1 / 288.4 / 291.2 |
| Bucket 筛选到 1 万行 | 202.8 | 217.7 |

| 筛选 XLSX 导出 | 58.3 | 90.3 |

短字段粘贴的最长主线程任务为 1,921–1,941 ms，中文为 5,686 ms；心跳最大延迟分别约 2.24–2.31 秒和 7.11 秒。纯文件导入与解析为 5,321.4 ms，仍有 1,076 ms 的主线程任务，因此改成文件导入本身也不能保证流畅。

首次基准使用默认 5 秒完成断言，中文第二文档导入超时。最终基准等待新页签可见就绪，并允许最多 30 秒观察完成；实际记录仍是 11.19 秒。没有把等待放宽当作性能通过，也没有修改应用来改善这份基线。

## 代码与数据指向的改造重点

1. **先治理原文输入。** 粘贴阶段没有调用 ImportEngine，仍有明显长任务。短字段第 1 次 paste→input 处理完成约 1,907 ms，Store.save 约 68 ms；中文分别约 5,656 ms 与 236 ms。CDP Nodes 在粘贴后约 20 万；它包含内部/尚未回收节点，不能解释为预览 DOM 有 20 万行。结合完整原文仍进入 textarea 的代码路径，支持优先实施已同意的摘要与有限预览，避免大原文完整插入编辑控件；仍需改造后对照实测确认收益。
2. **计算后台化需覆盖规范化与重复解析。** 短字段第 1 次 ImportEngine.parse 为 1,096.2 ms，其中 normalizeRows 约 822.5 ms，两者嵌套不能相加。创建 JOIN 的完整阶段包含再次解析约 980.8 ms，而 Joiner.run 两次共约 158.3 ms；不能把 2.81 秒全部归因于 JOIN 算法。后续需先明确数据集与查询版本，再消除无关状态变化触发的完整重算。
3. **分页缓存需要控制完整副本。** 短字段全量导出后 JS 堆约 175 MiB，连续翻页后约 225 / 275 / 325 MiB，缓存条目由 2 增到 5。代码的 QueryService 缓存键包含 stateRevision，每次未命中都会 `rows.map(row => row.slice())` 克隆全表。应将页码与完整查询结果的失效条件分开，限制缓存持有的数据量；这些阶段采样尚不能证明内存泄漏或准确进程峰值。
4. **大原文恢复必须更换同步保存路径。** 默认保存实测均遇到 localStorage 配额失败，内存原文仍保留；关闭页面后的自动恢复没有通过。临时模式控件没有写入绑定，取消勾选后 Store.persistRaw 仍为 true，报告明确记录，后续阶段按默认模式测量。大原文与小配置分离、异步保存及兼容迁移仍需决策和实现。
5. **容量与输出预算必须单独验收。** 短字段 UTF-8 11.80 MiB，项目文本估算 23.59 MiB；中文 UTF-8 14.96 MiB、估算 18.86 MiB。长字段 UTF-8 36.99 MiB、估算 73.98 MiB，粘贴仍耗时 4.42 秒，之后按现有上限明确拒绝解析且保留原文。这没有证明长字段解析能力。短/中文全量 XLSX 实际约 109.2 / 217.4 MiB，输入大小不能替代导出内存与输出预算。

短字段第二文档操作后的页面 JS 堆约 1.09 GiB；中文各阶段波动较大，最终操作后约 606 MiB。GC、临时字符串与缓存会影响阶段值；最初运行中文观察到更高的堆值，不能选较小数值当作容量保证。报告里的 performance.memory 采样与 CDP 值也不完全一致，后续以内存口径明确的对照实验制定预算。

## 尚未由基线解决的问题

这里建立可重跑的事实与优先级，没有实现 Worker、有限原文预览、异步恢复或新容量上限。共享 CI 各轮毫秒有波动，三次短样本不能得到可靠 p95；Linux headless 剪贴板也不代表所有系统或 Excel 富文本来源。

下一项独立任务是[单文件离线后台与恢复机制实测](../../.scratch/large-data-responsiveness/issues/09-chrome-offline-probes.md)，同样由 CI 驱动。直接 `file://`、首次无网络、Blob Worker、存储关闭重开/隐私条件仍需验证，再据此完成容量、取消与恢复契约。任何后续性能门槛应与正确性、原文完整保留、失败可恢复同时验收。
