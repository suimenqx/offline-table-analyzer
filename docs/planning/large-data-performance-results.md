# 10 万行 × 32 字段：22.1.1 性能改造结果

已实施并通过桌面 Chromium 验收。有限原文预览避开巨大 textarea 插入/布局，嵌入式 Worker 执行文本解析、查询、JOIN 和 XLSX，原文通过 IndexedDB 异步提交并恢复。仍是一个离线 index.html，零运行时依赖、零外部请求。架构、迁移与保护上限见[大数据 ADR](../architecture/large-data.md)。

## 与改造前比较

动作完成时间含自动化与两帧等待，不能当作真实用户 INP。短字段取三次中位数；主线程最长任务列给出三次范围。0 表示观察窗口内没有 ≥50 ms 的 Long Task，不能解读为没有 CPU 工作。旧报告见[改造前基线](ci-large-data-baseline.md)。

| 短字段阶段 | 改造前完成 ms | 22.1.1 完成 ms | 改造前最长任务 ms | 22.1.1 最长任务 ms |
| --- | ---: | ---: | ---: | ---: |
| 原生粘贴 | 2437.9 | 103.4 | 1921–1941 | 53–57 |
| 解析并显示第一页 | 1446.7 | 1922.5 | 1004–1155 | 0 |
| 全量 XLSX | 1840.7 | 2489.7 | 1483–1505 | 0 |
| 第 2 页 | 248.3 | 189.3 | 60–73 | 56–59 |
| 第 3 页 | 337.1 | 183.1 | 86–110 | 56–61 |
| 第 4 页 | 357.9 | 161.1 | 59–89 | 50–63 |
| Bucket 筛选 | 202.8 | 248.6 | 111–128 | 0 |
| 筛到 100 条 | 313.2 | 240.6 | 88–90 | 0 |
| 20 万行 JOIN 流程 | 2810.3 | 1941.3 | 1057–1070 | 0–53 |

原生粘贴约快 24 倍。中文 CRLF 粘贴由 7506.9 ms 降至 124.2 ms，最长任务由 5686 ms 降至 77 ms。37 MiB 长字段粘贴为 174.0 ms，最长任务 134 ms；此前该样本被旧上限拒绝，现在完成解析、筛选、复制、20 万行 JOIN 和导出。完整解析/导出的完成时间增加，工作移到后台并经过分批确认、预算检查，页面能够继续响应与取消；不是所有 CPU 任务都更快。

最终六个样本所有阶段的最大主线程任务为 134 ms，最大心跳延迟 239.2 ms。分页仍有约 50–70 ms 的 DOM 构建/布局任务，复制仍有约 95–98 ms 任务。这些是剩余开销，不宣称逐帧 60 FPS 或完全没有短暂卡顿。

分页没有继续生成全表副本：短字段页面 JS 堆由第一页约 102 MiB，在连续三次翻页后保持约 95–106 MiB；旧实现由约 175 MiB 增至约 325 MiB。CDP 只测 Window V8 堆，Worker 中还有一份数据和查询结果；不能把这些数值当作整个浏览器内存或宣称总内存同比下降。

文件导入使用 runner 本地文件路径，1900.0 ms 完成解析预览，没有观察到主线程长任务。此前 Playwright Buffer/base64 注入自身产生约 1–3 秒 Window 解码任务，文件阶段不能直接与该旧路径作产品速度倍数比较；原生粘贴及查询、导出路径维持一致。

## 正确性与恢复

[浏览器回归](../../e2e/large-data-flow.e2e.js)使用真实 100,000 × 32 中文 CRLF 原文，验证有限预览、字符串记录、修正覆盖层、原文完整导出、持久 profile 完全关闭重开、修正恢复、筛选 100 条、XLSX 独立读回以及关闭原文保存后重开为空。另覆盖取消大任务、再次解析后替换来源，确保旧结果不能覆盖新数据。扩大的恢复用例使用 90 秒完成断言超时，不代表允许阻塞 90 秒。

原文快照提交后才发布引用。设置/翻页复用快照，恢复取最新小设置与匹配原文，错误保留内存和旧提交；缺失快照阻止自动覆盖。取消计算不终止保存。临时模式清理完成前显示状态，关闭有提示，重开小存档会重试清理遗留快照。

构建器原有 String.replace 替换语法会改写源码中的 $$，已修复并加入 Worker 完整字节比较；已发布 21.x–22.1.0 的修正键迁移保留值并保证幂等。原文、字段字符串和 CLI 解析语义保持。

## 容量与适用范围

保护预算为每份原文 UTF-16 估算 128 MiB、工作区原文合计 256 MiB、解析/合计查询/导出 800 万单元格、每个 JOIN 100 万行、XLSX 256 MiB。超限明确报错，保留原文；预算不是所有浏览器都能达到的容量保证。当前测量证明的是这些代表性 10 万行样本。

巨大 HTML/DOMParser 仍走 Window，不纳入后台文本路径的响应承诺。file:// Blob Worker 和 IndexedDB 普通 profile 重开由[机制记录](../testing/baselines/2026-10-08-offline/offline-mechanisms.json)支持；同路径替换、改名/移动的 CI 结果不能推广到其他浏览器来源策略。隐私 context 关闭后不保留，存储失败仍需原文/工作区备份。

本地 Termux Node 与校验通过；Android Playwright 无法启动桌面 Chromium，Firefox 因系统 C++ 库符号不匹配未成功启动。本轮真实浏览器通过来自上述桌面 CI，手机开发者无需取得电脑基线或上传原文。
